# WxNodus 中文文案规范（docs/copy-guide.md）

> 原则：**专业术语保留，但首次出现必须附一句通俗解释；易懂但不失严谨。**

## 一、术语表（专业 + 通俗对照）

| 专业术语 | 保留用法 | 通俗解释（首次出现时附注） |
|---|---|---|
| agent | 保留 | 智能助手（执行任务的 AI 代理） |
| 工具（tool） | 保留 | 助手可调用的能力（读文件/执行命令等） |
| 会话（session） | 保留 | 一次对话的完整记录 |
| 上下文 | 保留 | 助手当前能看到的所有信息 |
| 模式（模式系统） | 保留 | 助手的行为规则（何时需要你确认） |
| 凭据 | 保留 | 账号密钥、访问令牌等敏感信息 |
| 硬红线 | 保留 | 任何情况下都不可执行的破坏性操作 |
| 概念编译器 | 保留（品牌名） | 把自然语言需求"编译"为可运行系统 |
| 黑洞引擎/召回 | 保留 | 历史记忆检索机制 |
| 审计链 | 保留 | 操作留痕记录（可追溯谁做了什么） |
| checkpoint（检查点） | 保留 | 快照：可回滚到某个时间点 |
| 审批/预审 | 保留 | 执行前征得同意；预审=由 AI 先判断 |
| 降级链 | 保留 | 主模型不可用时自动换备选模型 |

## 二、表达原则

1. **术语首次出现附解释**：如「凭据（账号密钥等敏感信息）」——专业词 + 括号说明。
2. **避免生硬英文直译**：不用 "please"、"TODO" 等夹生英文；可用行业通用词（agent/session/hook）但保持原文。
3. **避免口语化低端措辞**：不用「人话」「搞定」「整一个」等；用「简明解释」「完成」。
4. **错误提示友好化**：先说明发生了什么（专业），再给出怎么办（易懂）：
   - 例：`密钥无效或未配置（401）——请用 /key set <密钥> 重新配置`
5. **结论先行**：命令输出先给结果，再给细节。
6. **面向模型 vs 面向用户**：
   - 面向模型（系统提示/压缩器）：明确、结构化、术语准确（模型能理解专业词，无需过度解释）
   - 面向用户（命令输出/UI/错误）：术语 + 解释 + 行动指引

## 三、检查清单（提交文案前自查）

- [ ] 术语首次出现是否附解释？
- [ ] 有无口语化/低端措辞？
- [ ] 错误提示是否包含「发生了什么 + 怎么办」？
- [ ] 面向模型文案是否结构清晰、术语准确？
- [ ] 是否结论先行、便于快速浏览？
